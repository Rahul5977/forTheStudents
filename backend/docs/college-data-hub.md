# College Data Hub — Phase 12

> **Status:** 12a foundations built 2026-09-13 (schema, roster, validator, builder). Pilot collection next. See `progress.md` for the phase tracker; ADR-018 records the serving decision.
> **Owner:** Rahul. **Scope:** every IIT (23), NIT (31 + IIEST Shibpur), IIIT (28 JoSAA + IIIT Hyderabad / Bangalore / Delhi) — **86 institutes**.

## 1. Why

The AI Counsellor (`docs/ai-counsellor/Plan.md`, AC-ADR-001) is an *agent over our own tools*, not RAG: it only states facts that exist in the catalog and says "not in our data" otherwise. Until now the college content layer (`packages/catalog-core/src/content.ts`) held established year, website and NIRF rank for 43 institutes and `null` for everything else. The product goal is a CollegePravesh-style engineering hub: deep, sourced, per-college data for class 11/12 students, on top of the predictor and the mentor marketplace. The hub is that data layer, collected by parallel research agents and committed to the repo as reviewable JSON.

## 2. Layout

```
services/catalog/data/
  institutes.json                 canonical roster — 86 rows, generated by `hub:roster`
  colleges/
    <instituteId>/
      profile.json  academics.json  rankings.json          ← packet A
      placements.json  fees.json                           ← packet B
      campus-life.json  hostels.json  social.json          ← packet C
      alumni.json  faqs.json                               ← packet D
      seat-matrix.json                                     ← JoSAA-wide step (one agent, all ids)
      _meta.json                                           ← verifier bookkeeping
    coverage.json                 generated by `hub:validate`
    hub.bundle.json               generated by `hub:build`; imported by the catalog Lambda
packages/catalog-core/src/hub/    schema.ts (zod contract) · index.ts (loadHubBundle / hubFor / hubSection)
services/catalog/scripts/         hub-roster.ts · hub-validate.ts · hub-build.ts · hub-common.ts
```

Per-institute, per-section files so parallel agents write disjoint paths (no conflicts), diffs stay section-scoped (re-collect placements without touching campus life), and coverage falls out per section. The bundle gives the runtime single-file ergonomics.

## 3. The contract (`hub/schema.ts`)

- Every record that states a fact carries `sources[]` (≥ 1) and `asOf`. **No source → `null`.** Never fabricate.
- Facts are `nullable()`, never `optional()`. A missing key is a schema error (collector forgot); `null` is a deliberate "not published / not found".
- Objects are `strict()`: a typo'd key fails loudly.
- Prose surfaces (`about`, `summary`, FAQ answers, `note`s) are **original own-words text** with hard max lengths. Facts are not copyrightable; prose is. Never paste aggregator / Wikipedia / brochure narrative.
- `Source.confidence`: `official` (institute, NIRF, JoSAA, government), `secondary` (aggregators, press), `inferred` (derived by the collector — avoid). Aggregator hosts (`AGGREGATOR_HOSTS`) can never be `official` and never the sole source of a number.
- Social: official institutional / club / fest / placement-cell handles, plus publicly self-branded student or alumni creators with **≥ 10k followers**. Stored fields: platform, handle, URL, follower band, content type, affiliation. **No** emails, phones, DMs, private accounts, or minors' personal accounts.
- Photos are out of scope for the hub (they stay Wikimedia Commons + TASL in `content.ts`). Never re-host official-site images.

Sections and what they hold: `profile` (identity, about, location/connectivity, admission routes) · `academics` (departments → programs → intake, faculty count, curriculum highlights, research) · `placements` (per year: avg/median/highest, % placed, offers, PPOs, higher-studies %, top recruiters by sector, branch-wise when public) · `seat-matrix` (JoSAA program × quota × seat type × gender → seats; `null` for own-entrance institutes) · `fees` (per year split + scholarships) · `campus-life` (clubs by category, fests with month/footfall, sports) · `hostels` · `alumni` (public figures, ≤ 25) · `social` · `rankings` (NIRF overall + engineering per year, QS, NAAC) · `faqs` (5–15, own words).

## 4. Source priority (baked into every agent prompt as `RULES`)

1. Official institute site: placement-cell reports, fee circulars, hostel pages, academic prospectus, department pages.
2. `nirfindia.org` per-institute data (`IR-E-U-####` PDFs): median salary, % placed, higher studies, sanctioned intake, fees.
3. `josaa.nic.in`: seat matrix, business rules.
4. Official fest / club / society sites and their linked social accounts.
5. Wikipedia: **facts only** (established year, campus acres, notable alumni names); never its prose.
6. Careers360 / Shiksha / CollegeDunia / CollegePravesh / CollegeDekho: cross-check only → `confidence: "secondary"`.

`RULES` (verbatim, keep in sync with the workflow script):

```
RULES — College Data Hub collector
1. Read backend/packages/catalog-core/src/hub/schema.ts first. Your files MUST parse against it (strict keys, explicit nulls).
2. Source priority: official institute site > nirfindia.org per-institute PDF > josaa.nic.in > official fest/club sites > Wikipedia (facts only) > Careers360/Shiksha/CollegeDunia/CollegePravesh (cross-check only, confidence "secondary", never the sole source of a number).
3. Every record needs sources[] (>=1) with accessedOn = today and asOf = the year/date the page states. No source -> null. Never invent packages, footfall, faculty counts, seats, fees, acres.
4. Prose fields (about, summary, notes, FAQ answers) are ORIGINAL own-words text within the schema's max lengths. Never paste sentences from any site. Facts may be copied verbatim; prose may not.
5. Write EXACTLY the files listed for your packet, at the exact paths given, as valid JSON. Do not create other files. Do not touch any other institute's folder.
6. Placements: prefer the institute's placement-cell report; label the year the way the institute labels it (e.g. "2024-25"); branch-wise only when a public table exists.
7. Social: official handles from the institute's own site/footers; creators only if publicly self-branded as this institute's student/alumni with >=10k followers; store platform/handle/url/followerBand/contentType/affiliation only. No emails, phones, DMs, private or minors' personal accounts.
8. Photos/images: out of scope. Do not download or link images.
9. If a whole section is unavailable, write the section with empty arrays / nulls (still with a source for whatever you did find) rather than skipping the file; for nullable sections (seat-matrix, hostels) write the literal null.
10. Return only the manifest: files written, per-section coverage estimate (0–1), number of distinct sources, and an unresolved[] list of what you could not source.
```

## 5. Collection workflow

Orchestrated with the Workflow tool (owner authorised large multi-agent runs on 2026-09-13). Per institute, four collectors run in parallel, then one verifier; institutes flow through a `pipeline`, so verification of one starts while others are still collecting.

| Packet | Files | Effort |
|---|---|---|
| A | profile, academics, rankings | high |
| B | placements, fees | high |
| C | campus-life, hostels, social | high |
| D | alumni, faqs | high |
| V (verifier) | edits in place; writes `_meta.json` | xhigh |

The verifier is adversarial: it reads every file for the institute, picks 10 numeric facts spread across sections, fetches each cited URL and confirms the number appears there, sets unverifiable facts to `null`, deletes any prose run of ≥ 12 consecutive words that matches a source verbatim, and records `{checked, confirmed, nulled[], notes}` in `_meta.json`.

**Seat matrix** is collected once per season by a single agent over the JoSAA seat-matrix publication (latest year: 2026 if published, else 2025) and fanned out to every roster id; own-entrance institutes get `null`.

Batches: pilot 6 (`pilot: true` in the roster) → owner review → batches of ≤ 10 (~50 agents, ~60–80 min each). Failed packets are re-run with `resumeFromRunId` after editing only the failing prompt.

After every batch:

```sh
pnpm --filter @sc/catalog hub:validate     # zod + cross-file rules + coverage table → exit 1 on any error
pnpm --filter @sc/catalog hub:build        # → data/colleges/hub.bundle.json (runs validate first)
```

## 6. Serving (12c)

- `services/catalog/src/domain/hub.ts` imports `hub.bundle.json` (esbuild inlines it) and calls `loadHubBundle()` at module init.
- `GET /colleges/:id/profile` → `content.hub` = `hubFor(id)`; institutes with a hub record but no cutoff rows (own-entrance IIITs) return 200 with `branches: []` and identity from the roster.
- `GET /colleges/:id/hub/:section` → one section (400 on unknown section). Added to the CloudFront route list; no new query params.
- Frontend College Explorer replaces its four "Coming soon" cards with fees / seat matrix / placements / campus sections, each with a "Source: publisher · asOf" footer, and keeps the placeholder when a section is `null`.
- **ADR-018:** the hub is served from the committed bundle, not a DynamoDB table. It is read-only, a few MB, changes a few times a year, and needs zero infra. A `college_content` table is deferred until admin editing exists. If the bundle passes ~3 MB, seat-matrix rows move out of the bundle and are served lazily via `/hub/:section`.

## 7. Refresh cadence

| Data | Cadence | Packet |
|---|---|---|
| Seat matrix | every JoSAA season | seat-matrix step |
| Placements, fees, rankings | yearly (Oct–Dec, after placement reports) | B + rankings |
| Campus life, hostels, social | every 2 years | C |
| Alumni, FAQs, profile | every 2 years or on request | A, D |

`accessedOn` + `asOf` on every record let the counsellor caveat stale figures without a re-run.
